# 还没解决的问题

下面是从代码、测试和现场核验确认的缺口。它不是扩展产品的计划；先把现有功能和维护边界整理稳。修改相关模块时同步更新这一页，不保留已经完成的待办。

## 1. 生产服务仍有共用配置

2026-09-27 的只读核验确认：Cloudflare 当前只将班级站的聊天和语音路由绑定到 `mathclass-ai`，没有 Raccord Worker 路由。Raccord 仓库却仍配置了这个同名 Worker 和两个站点的路由，从同一账号发布仍可能覆盖班级站，Raccord 再次发布前必须消除这个冲突。

同日已在 Supabase 只读核对现役表、行策略、表授权和客户端角色。个人表按账号限制常规读写，但没有站点区分；两仓配置指向同一个项目，Raccord 也使用同名表，同一账号的记录仍共用。不能把代码拆仓或权限收紧称为完成了分库。

四张表的多余授权已于同日获用户授权后收紧，执行后的权限和匿名接口检查通过，原行策略保持不变。它解决了表授权过宽的问题，没有改变两个站点共用数据库的关系；实际权限见 [架构说明](architecture.md#数据表)。

服务器实际发布目录仍未核验。Raccord 根地址目前 301 跳到班级站。此次 Cloudflare 授权能查看 Worker，不能读取 DNS 和重定向规则，尚未定位跳转在哪一层配置。不能仅凭仓库已拆开就分别发布或删表。

班级站公开 health 仍是 2026-09-04 构建。线上 CSP 仍包含 Solana devnet，未包含首页天气的 Open-Meteo；仓库里的修正尚未上线。部署脚本已默认离线检查，固定目标目录并核验仓库、主分支和干净工作区。实际发布仍须用户授权。

相册建表、存储桶和综合授权保留在 `sql/legacy/`，与现役表定义、权限修正和只读核查分开。本轮生产变更只有已批准的四张表授权；没有读取或修改个人记录，没有重跑历史 SQL。

## 2. 自动检查还不能代替完整使用流程

导入边界已有 lint 约束，天气请求和动画生命周期也已有独立测试，hook 的 Supabase 导入也已禁止。这仍不是完整的架构验证。

CI 已加入 Chromium 的窄屏与桌面公开流程、模拟登录后的背词和答疑、平板导航及下载失败恢复检查，页面可见性包含透明度、视口位置与祖先裁切。答疑检查包括带令牌发送、认证失败后保留问题、保存后刷新读取。它不覆盖 Safari、真实移动设备、真实认证服务或完整跨账号流程。Worker 已纳入 lint，并覆盖权限、限流故障、语音、流式输入上限和取消；生产缓存、连接断开和模型可用性没有实测。

共用导航、翻页、文字按钮和提示样式已从首页、背词文件移到共享层，页面通过组件传入各自行为。基础样式的旧页面残留已清理，账号表单已归回登录样式。全局字体、窄屏留白和共享控件仍会影响多个页面；改这些规则需要实际页面验证。测试目标是发现真实顺序错误，不是单纯增加数量。

## 3. AI 服务的可用性与权限需要分开判断

仓库已让聊天和语音经过同一身份校验；前端带当前账号令牌，Worker 向 Supabase 核实。限流故障或校验超时会停止处理。代码已改不等于生产已生效：只读下载确认线上仍运行 2026-08-20 的无认证版本。部署时要先配置 Worker 的 `SUPABASE_URL`、`SUPABASE_ANON_KEY`，与前端一起发布核对；旧页面需刷新。Worker 生产配置尚未更新，也未调用真实模型。

背词朗读使用浏览器，未启用的 Worker 播放分支已删除；Worker 语音接口仍保留，要求认证，有 20 秒超时与音频格式检查。聊天模型列表查询失败时会使用写死的候选名称，代码不能证明这些模型当前一定可用。不要在说明里承诺“免费”或“始终可用”。
