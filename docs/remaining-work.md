# 还没解决的问题

下面是从代码和现有测试确认的缺口。它不是扩展产品的计划；先把现有功能和维护边界整理稳。修改相关模块时同步更新这一页，不保留已经完成的待办。

## 1. 资源推荐仍没有明确的处理流程

[ResourceCurate.jsx](../src/pages/ResourceCurate.jsx) 能提交推荐；旧审核和相册写入代码已经移除。页面明确说明不会自动公开，也不能查询审核进度。

是否保留这个入口、由谁处理队列，需要产品决定。不要为了让历史数据有用而重建管理后台。当前没有数据库级提交幂等标识，响应丢失后只能说明结果不明，不能保证刷新后再提交不会重复。

## 2. 历史配置与服务隔离还没核验完

相册建表、存储桶和授权仍在多个 SQL 中。仓库 Nginx 的 CSP 已移除 Solana devnet 并加入首页天气的 Open-Meteo 域名；生产是否使用这份配置未核验，也未发布。不能擅自执行 SQL。

部署脚本允许覆盖目标目录，未校验仓库和分支；Supabase 实例由环境变量指定。需要另行只读核对班级站和 Raccord 的实际服务、数据库与发布目标，才能判断生产是否真正隔离。

## 3. 自动检查还不能代替完整使用流程

导入边界已有 lint 约束，天气请求和动画生命周期也已有独立测试，hook 的 Supabase 导入也已禁止。这仍不是完整的架构验证。

测试目前没有自动浏览器层。页面等待、模块下载失败与入口脚本失败已有恢复提示，并用本地生产构建模拟故障验证；这些浏览器检查尚未自动化。Worker 已纳入 lint，并补了入口、CORS、限流、语音、流式输入上限和取消测试；实际 Cloudflare 行为仍未验证。

下一步应把少量最容易出错的浏览器流程纳入持续检查。测试目标是发现真实顺序错误，不是单纯增加数量。

## 4. AI 服务的可用性与权限需要分开判断

页面要求登录，但 [Worker 入口](../worker/src/index.js) 没有验证 Supabase 会话。CORS 只限制浏览器跨域读取，不是接口身份认证；限流绑定失败时仍会继续处理请求。

语音默认走浏览器，Worker 语音接口仍保留，已加 20 秒超时与音频格式检查。聊天模型列表查询失败时会使用写死的候选名称，代码不能证明这些模型当前一定可用。不要在说明里承诺“免费”“始终可用”或“只有登录用户能调接口”。
