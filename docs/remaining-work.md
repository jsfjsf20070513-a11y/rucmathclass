# 还没解决的问题

下面是从代码和现有测试确认的缺口。它不是扩展产品的计划；先把现有功能和维护边界整理稳。修改相关模块时同步更新这一页，不保留已经完成的待办。

## 1. 生产服务还没有证明已分离

2026-09-27 的只读核验确认：两仓本地 Supabase 配置相同，班级站线上脚本也指向该项目。Raccord 的 Worker 配置与班级站同名，并列出两个站点的路由。Raccord 根域名目前 301 跳到班级站。下一次发布前，需要查清 Cloudflare 实际绑定、数据库权限和服务器发布目录；不能仅凭仓库已拆开就分别发布或删表。

班级站公开 health 仍是 2026-09-04 构建。线上 CSP 仍包含 Solana devnet，未包含首页天气的 Open-Meteo；仓库里的修正尚未上线。部署脚本已默认离线检查，固定目标目录并核验仓库、主分支和干净工作区。实际发布仍须用户授权。

相册建表、存储桶和综合授权已移到 `sql/legacy/`，与现役个人表定义、只读核查分开；SQL 语句保持不变，未执行。以上核验没有查询数据库实际策略，也没有修改线上数据。

## 2. 自动检查还不能代替完整使用流程

导入边界已有 lint 约束，天气请求和动画生命周期也已有独立测试，hook 的 Supabase 导入也已禁止。这仍不是完整的架构验证。

CI 已加入 Chromium 的窄屏与桌面公开流程、模拟登录后的背词和答疑、平板导航及下载失败恢复检查，页面可见性包含透明度、视口位置与祖先裁切。它不覆盖 Safari、真实移动设备、真实认证服务或完整跨账号流程。Worker 已纳入 lint，并补了入口、CORS、限流、语音、流式输入上限和取消测试；实际 Cloudflare 行为仍未验证。

共用导航、翻页、文字按钮和提示样式已从首页、背词文件移到共享层，页面通过组件传入各自行为。基础样式的旧页面残留已清理，账号表单已归回登录样式。全局字体、窄屏留白和共享控件仍会影响多个页面；改这些规则需要实际页面验证。测试目标是发现真实顺序错误，不是单纯增加数量。

## 3. AI 服务的可用性与权限需要分开判断

页面要求登录，但 [Worker 入口](../worker/src/index.js) 没有验证 Supabase 会话。CORS 只限制浏览器跨域读取，不是接口身份认证；限流绑定失败时仍会继续处理请求。

语音默认走浏览器，Worker 语音接口仍保留，已加 20 秒超时与音频格式检查。聊天模型列表查询失败时会使用写死的候选名称，代码不能证明这些模型当前一定可用。不要在说明里承诺“免费”“始终可用”或“只有登录用户能调接口”。
